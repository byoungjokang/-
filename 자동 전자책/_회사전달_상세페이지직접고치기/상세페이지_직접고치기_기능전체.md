# 상세페이지 '글·사진 직접 고치기' 기능 · 전체 명세 + AI 지시문 + 원본 코드

- 기준: 전자책 생성기 **버전 2026.11.26a** (라이브 https://claude.ai/artifact/FAqAox5isaZSMtRTHRGroy 와 같은 코드)
- 위치: **09 상세페이지** 탭 → 휴대폰 미리보기 위 **"글·사진 직접 고치기"** 버튼
- 왜 만들었나: 수강생(40~60대 초보)은 결과를 복사·붙여넣기만 할 줄 알고 '수정 요청' 문장을 못 써요. 그래서 미리보기에서 **고칠 글이나 사진을 누르면 바로 고치는 칸이 열리게** 했어요.
- 이 기능이 AI에게 보내는 지시문은 **1개**예요(한 문장 다시 쓰기). 나머지는 화면·데이터 처리라서, 회사 프로그램에 그대로 옮길 수 있게 **동작 명세 + 원본 코드 전체**를 넣었어요.

---

## 1. 사용자가 보는 흐름

1. 상세페이지가 만들어진 뒤 **"글·사진 직접 고치기"**를 누르면 미리보기의 모든 글과 사진에 노란 점선이 생김 (FAQ는 답까지 펼침, 등장 효과·흐르는 후기 캡처는 멈춤)
2. **글을 누르면** 아래쪽에 고치는 칸(시트)이 열림
   - 그 칸의 원래 글이 들어 있음 (강조 기호 `{accent}` 등은 빼고 보여 줌)
   - 직접 고치고 **저장**
   - **AI에게 맡기기**: "더 짧게", "더 쉽게", "더 끌리게" 버튼, 또는 "이렇게 바꿔 줘" 한 줄 입력 → AI가 그 문장 하나만 고쳐서 칸에 넣어 줌 → 마음에 들면 저장
   - 글을 다 지우고 저장하면: 목록 안 항목이면 그 항목을 빼고, 아니면 빈칸으로
   - 사진을 넣을 수 있는 섹션이면 시트에 **"이 섹션에 ○○ 넣기 / ○○ 바꾸기"** 버튼도 보임
3. **사진을 누르면** 시트가 사진 모드로 열림: 지금 사진 미리보기 + **다른 사진으로 바꾸기**(파일 올리기) + **사진 빼기**
4. 사진이 없는 섹션에는 미리보기 안에 **"＋ 여기에 ○○ 넣기"** 버튼이 생김 → 누르면 바로 파일 고르기. 후기 섹션은 항상 **"＋ 후기 캡처 사진 넣기"**(여러 장)
5. 저장할 때마다: 상세페이지 HTML을 다시 만들고, 미리보기는 **보던 위치 그대로** 다시 그림, 승인은 풀림("고친 내용을 확인하고 다시 '승인'"), 자동 저장
6. **"고치기 끝내기"**를 누르면 점선이 사라지고 원래 미리보기로

## 2. 데이터와 규칙

### 2-1. 고칠 수 있는 칸
상세페이지 내용 JSON(`spData`, ebook-salespage 스킬의 `08_salespage.json` 형식)의 **모든 글자(문자열) 칸**을 고칠 수 있어요. 단 아래는 빼요.
- `meta.*` (책 이름·결제 링크·브랜드 등 생성기가 정하는 사실), `topbar.*`
- 사진 칸: 경로에 `cover`, `photo`, `image`, `images`, `captures`가 들어간 칸
- 빈 글자

### 2-2. 사진 칸 (섹션 → JSON 칸)

| 섹션 | JSON 칸 | 이름 | 비고 |
|---|---|---|---|
| hero | `hero.cover` | 표지 사진 | 760px로 줄여 data URL |
| story | `story.photo` | 저자 사진 | 760px |
| reason | `reason.image` | 설명 그림 | 760px |
| dig | `dig.image` | 그림 | 760px |
| reviews | `reviews.captures` (배열) | 후기 캡처 사진 | 900px, 여러 장, 이름·프로필은 가리고 올리라고 안내 |

- 올린 사진은 JPG로 줄여(`shrink`) **data URL로 HTML 안에 넣어요** (원래 표지도 같은 방식, 640px).
- 사용자가 올리거나 뺀 사진은 `spUserImg` = `{ _key: 책 키, "story.photo": url, "hero.cover": "" (뺀 것), "reviews.captures": [url…] }`에 기록해요. AI로 '수정 요청'·'다시 만들기'를 해도 생성기가 사진 칸을 정리하는 단계(`spFixFacts`) 끝에서 다시 씌워요(`spApplyUserImg`). **같은 책일 때만**(`_key`가 지금 책 키와 같을 때) 씌워요.
- `spUserImg`는 작업 자동 저장(localStorage)·작업 파일에 같이 저장돼요.

### 2-3. 글 저장 규칙
- 줄표(— –)는 쉼표로, 화살표(→)는 빈칸으로, ` · `는 쉼표로, 이모지는 지움 (`spRule`, 생성기 금지 문자 규칙과 같음)
- 원래 글에 `{accent}…{/accent}`, `{b}`, `{muted}`, `{u}` 강조가 있었고 그 말이 고친 글에 그대로 남아 있으면 강조를 다시 씌움 (`spReTag`)
- 바꾼 게 없으면 그냥 닫음

### 2-4. 어떤 글을 눌렀는지 아는 방법 (핵심 아이디어)
상세페이지 HTML은 JSON을 빌더(`spBuild`)로 바꿔서 만들어요. 그래서 화면 글자만 보고는 JSON의 어느 칸인지 알 수 없어요.
1. 고치기 모드에서는 JSON을 복사해서 **글자 칸마다 끝에 보이지 않는 표시(영폭 문자)**를 붙여요. 표시는 칸 번호를 4진수로 바꾼 것: 시작 `U+2063` + 숫자(`U+200B`=0, `U+200C`=1, `U+200D`=2, `U+2060`=3) + 끝 `U+2064`. 칸 번호 → JSON 경로 표(`spEditPaths`)를 같이 만들어요.
2. 그 JSON으로 빌드한 HTML을 미리보기(iframe srcdoc, 같은 출처)에 넣어요.
3. 미리보기 문서의 글자 노드를 훑어 표시를 찾고, 표시는 지우고, 그 글자를 담은 요소에 `data-sp="칸 번호"`를 붙여요. 강조 태그(`strong`, `u`, `span.accent`, `span.muted`) 안이면 바깥 요소로 올라가요. 한 요소에 칸이 두 개 들어 있으면 두 번째부터는 그 글자를 `<span data-sp>`로 감싸요.
4. 사진(`img`)은 들어 있는 `section`의 첫 `data-sp` 칸 경로 맨 앞(섹션 이름)으로 어느 섹션인지 알아요 (hero는 `section.hero`).
5. 문서에 클릭 가로채기(capture 단계)를 걸어 링크·버튼·체크·FAQ 열고 닫기를 막고, 누른 곳에 따라 시트를 열어요.
6. **복사·저장되는 HTML(`spHtml`)은 표시 없는 원래 JSON으로 따로 빌드**해서 표시가 절대 섞이지 않아요.

> 회사 프로그램에 옮길 때: 빌더가 다르면 이 방식(문자열 끝 영폭 표시 → 렌더 후 찾기)은 빌더를 고치지 않고 그대로 쓸 수 있어요. 빌더가 글자를 자르거나(slice) 속성(href·alt)에 넣는 칸만 빼 주면 돼요. 빌더를 직접 고칠 수 있다면 각 글 요소에 `data-path="story.timeline.0.text"`를 바로 넣는 게 더 단순해요.

## 3. AI 지시문 (한 문장 다시 쓰기) · 원본 그대로

시트의 "더 짧게 / 더 쉽게 / 더 끌리게" 버튼이나 "AI로 바꾸기"를 누르면 이 지시문 하나를 보내요. `sample(prompt, { modelTier: "default", cache: false, onText })` 로 글자가 나오는 대로 칸에 채워요. 결과 앞뒤 따옴표는 지워요.

```js
    const prompt = `너는 한국 전자책 판매 상세페이지의 문장을 다듬는 카피 편집자다. 아래 [지금 문장] 하나만 [요청]대로 고쳐 쓴다.
- 고친 문장만 출력한다. 따옴표, 설명, 머리말을 붙이지 않는다.
- 뜻과 사실은 그대로 둔다. 숫자·이름·기간·후기·성과를 바꾸거나 새로 지어내지 않는다.
- 줄 수와 길이는 [지금 문장]과 비슷하게 (줄바꿈이 있으면 줄바꿈도 비슷하게). 버튼 글이면 12자 이하.
- 줄표(—, –), 화살표(→), 이모지, 영어 대문자 라벨은 쓰지 않는다.
- 50~60대도 바로 읽히는 쉬운 우리말로 쓴다.

[책 제목] ${spData?.meta?.book || ""}
[이 문장이 있는 곳] ${SP_SECN[spSel.sec] || spSel.sec} 섹션 · 칸 이름 ${spSel.path.join(".")}
[요청] ${ask}
[지금 문장]
${before}`;
```

버튼마다 `${ask}`에 들어가는 글:

| 버튼 | `ask` |
|---|---|
| 더 짧게 | `뜻은 그대로 두고 더 짧게` |
| 더 쉽게 | `50~60대도 바로 알아듣게 더 쉬운 말로` |
| 더 끌리게 | `읽는 사람이 더 궁금해지고 끌리게` |
| AI로 바꾸기 | 사용자가 입력한 한 줄 그대로 (예: `30대 직장인 말투로`) |

나머지 자리: `${spData?.meta?.book}` 책 제목, `${SP_SECN[spSel.sec]}` 섹션 한글 이름, `${spSel.path.join(".")}` JSON 칸 경로(예: `hero.h1`), `${before}` 시트에 지금 들어 있는 글.

오류 처리: AI를 못 쓰는 화면이면 "이 화면에서는 AI를 쓸 수 없어요. 글을 직접 고친 뒤 '저장'을 누르세요.", 실패하면 원래 글로 되돌리고 오류 문구.

### 4-3. 기능 JS 전체 (`// ── 상세페이지 직접 고치기 (11.26a) ──`부터)

```js
  // ── 상세페이지 직접 고치기 (11.26a) ──
  // 초보는 '수정 요청'을 쓸 줄 몰라서, 휴대폰 미리보기에서 글·사진을 눌러 바로 고치게 한다.
  // 글마다 보이지 않는 표시(영폭 문자)를 붙여 빌드한 뒤 미리보기 안에서 표시를 찾아 어떤 칸인지 안다. 복사·저장되는 HTML(spHtml)에는 표시가 없다.
  const SP_IMG = { hero: ["cover", "표지 사진"], story: ["photo", "저자 사진"], reason: ["image", "설명 그림"], dig: ["image", "그림"], reviews: ["captures", "후기 캡처 사진"] };
  const SP_SECN = { hero: "첫 화면", story: "저자 이야기", selfcheck: "셀프체크", reason: "진짜 이유", dig: "파고들기", reality: "리얼리티 체크", diff: "3가지 차이", toc: "목차", results: "실제 성과", reviews: "후기", honest: "정직 선언", faq: "자주 묻는 질문", price: "가격" };
  let spEditOn = false, spEditPaths = [], spSel = null, spUserImg = {}, spAiCtl = null;
  const ZW = ["​", "‌", "‍", "⁠"], ZS = "⁣", ZE = "⁤";
  const zwEnc = (n) => ZS + n.toString(4).split("").map(c => ZW[+c]).join("") + ZE;
  const zwRe = new RegExp(ZS + "([" + ZW.join("") + "]+)" + ZE, "g");
  const zwDec = (z) => parseInt([...z].map(c => ZW.indexOf(c)).join(""), 4);
  const spGet = (o, path) => path.reduce((a, k) => a == null ? a : a[k], o);
  const SP_TAG = /\{(accent|b|muted|u)\}([\s\S]*?)\{\/\1\}/g;
  const spPlain = (x) => String(x || "").replace(/\{\/?(accent|b|muted|u)\}/g, "");
  function spMarked(d) {
    spEditPaths = [];
    const walk = (o, path) => {
      if (typeof o === "string") {
        if (!o.trim() || path[0] === "meta" || path[0] === "topbar" || path.some(k => /^(cover|photo|image|images|captures)$/.test(k))) return o;
        spEditPaths.push(path); return o + zwEnc(spEditPaths.length - 1);
      }
      if (Array.isArray(o)) return o.map((x, i) => walk(x, path.concat(i)));
      if (o && typeof o === "object") { const c = {}; for (const k of Object.keys(o)) c[k] = walk(o[k], path.concat(k)); return c; }
      return o;
    };
    return walk(d, []);
  }
  function spApplyUserImg(d, I) {
    if (!spUserImg._key || spUserImg._key !== spKeyOf(I)) return;
    Object.entries(spUserImg).forEach(([k, v]) => {
      if (k === "_key") return; const [sec, f] = k.split("."); if (!d[sec] || typeof d[sec] !== "object") return;
      if (Array.isArray(v)) { if (v.length) d[sec][f] = v.slice(); else delete d[sec][f]; }
      else if (v) d[sec][f] = v; else delete d[sec][f];
    });
  }
  function spFrameLoad(html, keepY) {
    const fr = $("salesFrame"); let y = 0;
    try { y = keepY ? fr.contentWindow.scrollY || 0 : 0; } catch (e) {}
    fr.onload = () => { try { if (spEditOn) spWire(fr.contentDocument); if (y) setTimeout(() => fr.contentWindow.scrollTo(0, y), 60); } catch (e) {} };
    fr.srcdoc = html;
  }
  const spSecOf = (el, doc) => { const sec = el.closest("section"); const m = sec && sec.querySelector("[data-sp]"); return m ? spEditPaths[+m.getAttribute("data-sp")]?.[0] : (sec?.classList.contains("hero") ? "hero" : ""); };
```

## 5. 같이 쓰는 기존 함수 (참고 · 원본 그대로)

이 기능은 아래 기존 함수를 그대로 불러 써요. 회사 프로그램에서는 같은 역할을 하는 함수로 바꿔 끼우면 돼요.

| 함수 | 하는 일 |
|---|---|
| `spBuild(d, pal, pId)` | 상세페이지 JSON → HTML (ebook-salespage 빌더) |
| `spShow()` | 요약·미리보기·HTML 코드 칸 갱신 |
| `spFixFacts(d, I, coverUrl)` | AI 결과에 사실 칸(책 이름·표지·후기·가격) 채우고 금지 문자 정리 |
| `spKeyOf(I)` | 지금 책을 구분하는 키 |
| `shrink(blob, max)` | 사진을 긴 변 max px JPG(품질 0.9)로 줄이기 |
| `blobToUrl(blob)` | 파일 → data URL |
| `autoSave()` | 작업 자동 저장 |
| `samplePromise` | 보는 사람 계정의 Claude 호출 (`window.claude.use("sample")`) |
| `noteFn(id)`, `$(id)`, `ERR` | 안내 문구 표시, 요소 찾기, 오류 문구 표 |

- [ ] 결과 미리보기가 같은 출처 iframe(또는 같은 문서 안)이라 안쪽 DOM을 만질 수 있는가 (다른 출처면 postMessage로 클릭 위치·칸 번호를 받아야 함)
- [ ] 고칠 칸 목록에서 사실 칸(책 이름·결제 링크·가격 숫자 등 프로그램이 정하는 값)을 뺐는가
- [ ] 복사·저장용 HTML은 표시 없는 원본으로 다시 빌드하는가
- [ ] 사용자가 올린 사진이 AI 재생성 뒤에도 남는가 (같은 책일 때만)
- [ ] 고친 뒤 미리보기가 보던 위치를 유지하는가
- [ ] 고치면 승인(확정) 상태를 풀고 다시 확인하게 하는가
- [ ] 금지 문자 자동 정리(줄표·화살표·이모지)를 저장 때 하는가
- [ ] 후기 캡처 안내: 이름·프로필은 가리기, 지어낸 후기 금지
- [ ] AI 버튼은 그 문장 하나만 보내는가 (전체 JSON을 다시 만들지 않음 → 빠르고 다른 칸이 안 바뀜)
