# 상세페이지 구조 명세 — 리치코드 12섹션 + 선택 모듈 3

리치코드(https://lifeschool.crekit.io/new-page) 실제 구조를 그대로 옮긴 것이다. 섹션 번호·순서가 정본이다.
흐름은 **광고 연결 → 저자 이야기 → 내 이야기 → 원리 → 통념 부정 → 차별점 → 목차 → 증거 → 후기 → 정직 → FAQ → 가격** 이다.
"문제 인식 → 공감 → 신뢰 → 해법 → 증거 → 제안 → 마감" 의 순서를 전자책 한 권에 맞게 접은 형태다.

각 섹션은 `목적 / 배경 / 슬롯 / 길이 / 규칙 / 리치코드 원문` 으로 적는다. 배경 `deep` 은 한 단계 더 어두운 면, `base` 는 기본 면 — **deep 과 base 가 번갈아** 리듬을 만든다.

---

## 00. 상단 바 (topbar) — 선택
- 목적: 마감 시각 상시 노출. 가격 사다리를 쓸 때만.
- 슬롯: `topbar.text` ("오늘 얼리버드 마감까지") + 카운트다운(자동, 밤 11시 59분 KST).
- 규칙: "자정"이라고 쓰지 않는다 → "밤 11시 59분". 사다리가 없으면 상단 바를 빼라.

## 01. 히어로 (hero) — base
- 목적: **광고 첫 문장을 그대로 이어받는다.** 광고를 누른 사람이 같은 문장을 다시 보게.
- 슬롯: `brand` (책 이름 + 형태, 예: "리치코드 · 현실창조 PDF"), `h1` (2~3줄, 세리프), `story` (3~4문장, strong 2개, 마지막 문장은 액센트), `cta` (버튼 1 + 텍스트 링크 1 "이야기 먼저 읽기" → #story), `cover` (표지 이미지 + 캡션 "88페이지 PDF, 평생 소장").
- 길이: h1 ≤ 3줄·각 줄 ≤ 10자. story ≤ 120자.
- 규칙: 히어로에 텍스트 요소 4개까지(brand·h1·story·cta). 신뢰 띠·가격·기능 목록을 히어로에 넣지 않는다. 제목은 **장면 한 컷**이지 책 소개가 아니다 ("7년 전, 저는 방 밖으로 나가지 않았습니다.").
- 원문: h1 "7년 전, / 저는 방 밖으로 / 나가지 않았습니다." story "스물다섯, 우울증이었습니다. 돈도, 사람도, 내일도 다 포기하고 싶었습니다. 그 방에서 7년 동안 수백 권을 읽고 찾은 답은 하나였습니다. 노력이 아니라, 무의식이 문제였습니다."

## 02. 저자 이야기 (story) — deep, id="story"
- 목적: 히어로의 장면을 **시간순 5단계**로 풀어 신뢰를 만든다. 비포/애프터 사진 1장.
- 슬롯: `h2` (2줄, 둘째 줄 액센트), `photo` + 캡션, `timeline[5]` (각 `label` + `text`, 4번째는 `turn`(전환), 5번째는 `hit`(현재) + `wins[3~5]`), `codeLine` (섹션 마감 한 줄: "그 7년의 노하우와 정수를 / 88페이지에 담았습니다.").
- 길이: 타임라인 항목 ≤ 90자. wins 각 ≤ 20자.
- 규칙: 라벨은 나이·사건·기간 같은 **사실 단어** ("25살", "7년, 수백 권", "지금"). 성과 wins 는 intake 에 있는 것만. 사진 없으면 figure 를 뺀다(자리 비워두지 않는다).
- 모듈 A: 원료 경로가 `경험 없음` 이면 타임라인 대신 **탐구형 서사**(왜 이 주제를 파게 됐나 → 무엇을 모았나 → 무엇을 확인했나 3단) 로 바꾼다. 1인칭 고백 금지.

## 03. 셀프체크 (selfcheck) — base
- 목적: 저자 이야기를 **독자 이야기**로 넘긴다. 누르면 체크되는 버튼 3~5개.
- 슬롯: `h2` ("혹시, / 당신 이야기인가요?"), `lead` ("해당되는 항목을 눌러보세요."), `items[3~5]`, `result` ("하나라도 해당된다면, / 7년 전의 저와 같은 자리에 계신 겁니다.").
- 규칙: 항목은 `02_market.md` 고객 언어 원문을 다듬어 쓴다. 보는 사람을 단정하는 2인칭 꼬리표("당신 모솔이죠?") 금지 — 행동 묘사로 쓴다("월급 받자마자 다음 달 카드값부터 걱정한다").

## 04. 진짜 이유 (reason) — deep
- 목적: 문제의 **원리 하나**를 보여준다. 숫자 하나 + 그림 하나 + 본문 3문단 + 판결문.
- 슬롯: `h2` (3줄까지, 가운데 줄 액센트), `ratio` (두 값 비교 막대, 예: 의식 10% / 무의식 90%; 없으면 생략), `ratioCap`, `image`, `body[3]`, `oldVoice[2]` (낡은 혼잣말 인용), `verdict` (3줄, 마지막 줄 액센트).
- 규칙: 원리는 `02_research.md` 에 근거가 있는 것만. 비율 막대는 실제로 자주 인용되는 수치일 때만 쓰고 출처를 캡션에 짧게 둔다. 없으면 막대를 빼고 본문으로 간다.

## 05. 리얼리티 체크 (reality) — base
- 목적: 시장에 흔한 조언 3개를 늘어놓고 **"결과로 안 이어지는 것은 무시하라"** 고 선을 긋는다.
- 슬롯: `h2` ("끌어당김 콘텐츠는 / 이미 많습니다"), `advice[3]` (따옴표 문장), `body`, `ignore` (박스 한 줄, 액센트 단어 1개), `forYou` ("리치코드는 / 그다음을 알려주는 책입니다.").
- 규칙: 경쟁 콘텐츠 이름을 찍지 않는다. 조언 문장은 실제 시장에 흔한 말로.

## 06. 3가지 차이 (diff) — deep
- 목적: 이 책의 방법 3개. 첫 번째가 가장 크고(세로 2칸), 나머지 둘은 작게.
- 슬롯: `h2` ("리치코드는 / 3가지가 다릅니다"), `items[3]` (`title` 2줄까지 + `text` ≤ 80자), `faster` ("저는 이 방법을 찾기까지 7년이 걸렸습니다. 하지만 여러분은 훨씬 빠르게 시작할 수 있습니다.").
- 규칙: 제목은 **"A가 아니라 B"** 꼴이 가장 세다("확언이 아니라 가난을 만드는 각인 삭제법"). 3개를 넘기지 않는다. 똑같은 크기 카드 3개 나열 금지(첫 칸을 키운다).

## 07. 목차 (toc) — base, id="contents"
- 목적: 분량과 구성을 숫자로 보여주고 파트 묶음별 챕터 4개씩.
- 슬롯: `h2` ("리치코드 목차"), `meta[2]` ("총 88페이지", "9부 구성"), `parts[3]` (`label` "PART 1-2", `title` 2줄, `items[4]`).
- 규칙: `03_outline.json` 제목을 **그대로**. 파트가 많으면 3묶음으로 접는다(PART 1-2 / 3-4 / 5-9). 본문 미리보기 이미지는 넣지 않는다(목차만).

## 08. 실제 성과 (results) — deep — 재료 없으면 생략
- 목적: "너만 된 거 아니냐"에 캡처로 답한다.
- 슬롯: `h2` ("'너만 된 거 아니냐?' 하는 분들에게"), `lead`, `images[2~6]` (클릭 시 원본), `notes` ("※ 이미지를 누르면 크게 볼 수 있습니다 / ※ 후기가 조작일 시 100% 환불").
- 규칙: 캡처는 실제 것만. 개인정보(이름·ID)는 앞부분만 가린다.

## 09. 후기 + 중간 CTA (reviews) — base
- 목적: 후기 4~6개, 2열 카드. 바로 아래 중간 구매 버튼(감정이 올라온 지점).
- 슬롯: `h2` ("먼저 읽은 분들의 / 이야기"), `items[4~6]` (`quote` ≤ 160자, `who` "30대 직장인, 서울"), `midCta` ("39,000원에 리치코드 받기").
- 모듈 B: 카페·카톡 **캡처 후기**가 있으면 카드 아래에 가로 자동 스크롤 슬라이드(10장까지)와 보장 띠("이 후기가 조작일 시 천만원을 드리겠습니다.")를 붙인다. 캡처는 소속·상호 가린 원문 그대로. 보장 띠 문구와 금액은 사용자가 정한다.
- 모듈 C(임시 후기): 실제 후기가 아직 없으면 **임시 후기 6개를 써서 넣는다.** 타깃의 고객 언어(02_market)로 쓰고 각 항목에 `sample:true` 를 단다. 빌더가 "임시 후기 N개"를 알려 주고, 사용자는 발행 전에 실제 후기로 바꾼다.

## 10. 정직 선언 (honest) — deep, 가운데 정렬
- 목적: 가격 직전에 **과장 문구를 취소선으로** 걸고 "이런 말로 현혹하지 않겠다" 고 말한다. 그러고 나서 진짜 차이 한 문장.
- 슬롯: `hype[2~3]` ("'인생이 180도 바뀝니다'"), `h2` ("이런 말로 / 현혹하지 않겠습니다."), `body` (strong 1개).
- 규칙: 좁은 폭(720px). 여기서만 가운데 정렬을 쓴다.

## 11. FAQ (faq) — base
- 목적: 망설임 5개. 왼쪽 제목, 오른쪽 아코디언.
- 슬롯: `h2` ("자주 묻는 / 질문"), `items[5]` (`q`, `a` ≤ 160자).
- 규칙: 앞 2개는 시장의 망설임("초보도 되나요", "몇 년 해봤는데 안 됐어요"), 3번째는 손실 회피("이걸 안 보면 어떻게 되나요"), 뒤 2개는 분량·기한 / 확인 방법 고정. 환불은 "열람 전 전액 / 열람 후 제한 / 판매자 귀책 시 법령" 3단으로.

## 12. 가격 (price) — deep, id="price"
- 목적: 선택 질문 → 가격 카드(배지·정가 취소선·현재가·사다리·타이머·버튼·안내).
- 슬롯: `choice` (2줄 질문, 둘째 줄 흐리게), `body`, `card.tag` ("얼리버드 80% OFF"), `card.was` ("정가 198,000원"), `card.now` (39,000), `ladder[3~4]` (`step`, `price`, `state`: 종료/현재/예정), `timerText` ("오늘 밤 11시 59분 종료 후 정가로 전환됩니다"), `btn`, `fine` ("결제 즉시 다운로드, 평생 소장").
- 규칙: 숫자는 사용자가 준 것만. 사다리를 안 쓰면 ladder·timer·topbar 를 모두 뺀다(셋은 한 세트). 마감 후 정가로 바뀌면 "지금 안 사면 더 비싸진다" 류 문구를 지운다.

## 13. 푸터 + 스티키 바
- 푸터: "© {브랜드}. ALL RIGHTS RESERVED" 한 줄. 익명 브랜드면 브랜드명만.
- 스티키: 정가 취소선 + 현재가 + 마감 카운트 + 버튼. 크레킷 iframe 에서는 고정이 안 되므로 **크레킷 고정 CTA 기능**을 쓰고 HTML 의 스티키는 `stickyBar:false` 로 끈다.

## 선택 모듈 요약
| 모듈 | 언제 | 어디에 |
|---|---|---|
| A 탐구형 서사 | 저자 경험 없음 | 02 저자 이야기 대체 |
| B 캡처 후기 슬라이드 + 보장 띠 | 캡처 후기 있음 | 09 후기 카드 아래 |
| C 임시 후기 | 실제 후기 0개 | 09 에 sample:true 후기로 채움, 발행 전 교체 |
| D 파고들다 (dig) | 저자가 자료·논문을 모은 과정 사진이 있을 때 | 04 진짜 이유 뒤 (사진 1 + 메모 3) |

## 섹션별 배경 리듬 (바꾸지 않는다)
hero base → story deep → selfcheck base → reason deep → reality base → diff deep → toc base → results deep → reviews base → honest deep → faq base → price deep. 섹션을 빼면 남은 것끼리 다시 번갈아 칠한다(빌더가 자동).
