# 파이프라인 계약 — 단계별 입력·출력·승인 규칙

책 하나 = 폴더 하나 (`books/<slug>/`). 모든 단계는 **파일을 남기고 멈춘다.** 대화가 끊겨도 폴더만 있으면 이어서 간다.

```
books/<slug>/
  pipeline.json      진행 상태 (status.js 가 읽고 씀)
  00_intake.md       입력 폼 (사용자가 채움)
  00_voice.md        문체 가이드 (문체 (b) 선택 시 생성)
  01_onething.md     1-2 주제 쪼개기 결과 + 확정 원씽 한 문장
  02_market.md       1-3a 7채널 시장 검증 + 고객 언어 + 10주제 표 (market-validation.md)
  02_research.md     1-3b 심화 리서치 보고서
  03_outline.json    1-4 목차 (챕터·트랙·자극·문법·주장·결론·원료 매핑)
  04_book.json       1-5 원고 (빌더 스키마, 챕터 단위로 누적 저장)
  04_review.md       1-5 검수 기록 (챕터별 체크리스트 결과)
  05_ebook.docx      1-6 출력
  05_ebook.pdf
  05_ebook_sheet.png 전체 페이지 축소판 (눈 검수용)
  09_hooks.md        09 후킹 뱅크 30개 + 사용자가 고른 20개 (ebook-meta-ads)
  09_ads.json        09 광고 소재 내용 (형식 배정·문구·인물 장면, ads-schema.json)
  ads/people/        09 인물 사진 (ChatGPT 원격 생성)
  ads/out/           09 소재 PNG 1080x1350 (NN.png)
  09_ads_sheet.png   09 소재 전체 시트 (눈 검수·소재 15개 고르기용)
  09_upload_plan.md  09 본문·헤드라인 + 메타 업로드 계획
  09_launch_log.md   09 업로드 기록 (업로드했을 때만, 광고 ID 포함)
```

## 승인 게이트 (mode: step-confirm)

각 단계가 끝나면 **① 산출물 파일 저장 → ② 요약을 화면에 보여줌 → ③ "승인 / 수정 요청 / 다시" 를 기다림.**
승인되면 `status.js --set <단계> approved` 로 기록하고 다음 단계로. 수정 요청이면 같은 단계를 고쳐서 다시 보여준다.
승인 없이 다음 단계로 넘어가지 않는다. 사용자가 "끝까지 알아서 해" 라고 하면 `pipeline.json` 의 `mode` 를 `auto` 로 바꾸고 게이트를 건너뛴다 (단, 집필 checkpoint 는 auto 에서도 한 번 멈춘, 09 의 승인 ③ 업로드·예산은 auto 에서도 반드시 멈춘다).

요약은 짧게: 무엇을 만들었고, 사용자가 판단해야 할 지점이 무엇인지 (예: "추천안은 2안 뼈대 + 3안 살입니다. 챕터 07 도발 제목이 세니 확인 바랍니다").

## 단계별 계약

### 00 입력 (intake)
- 입력: 사용자 답변 → `00_intake.md`
- 필수 항목(`*`)이 비면 그 항목만 다시 묻는다. 한 번에 다 묻지 않고 빈 것만.
- B 주제는 정해진 순서로 묻는다: 카테고리 체크 → "이미 주제를 정하셨나요?" → (정했다: 주제 한 줄 → 추천 더 받기 / 바로 생성) · (확실하지 않다·미정: "주제 쪼개기로 추천해드릴까요?" → 후보 → 선택). 자세한 문구는 `intake.md` B.
- C 원료는 확정 주제를 넣은 5문항. 1번 `경험 없음` → 2~5 건너뛰고 리서치·쪼개기 추천 경로 → 선택 후 2·5번만 → 연구·사례 기반 톤 플래그를 `00_intake.md` 에 남긴다 (`원료 경로: 경험 없음`). 03 목차·04 집필은 이 플래그를 보고 프롤로그를 고백형이 아닌 탐구형으로 짠다.
- 문체 (b) 면 `voice-extract.md` 절차로 `00_voice.md` 생성.
- 저자가 병조쌤 본인이 아닌데 문체 (a) 를 골랐으면 (c) 또는 (b) 로 바꾸도록 안내한다 (bj-essay-voice 는 본인 전용).
- 출력 요약: 저자/주제/문체/템플릿/분량 한 줄씩.

### 01 주제 쪼개기 (1-2, `ebook-topic-split`)
- 입력: intake B + C
- 절차: 스킬 그대로 — 5개의 칼로 10개 이상 → 한 문장 → 4테스트 → 추천 1개 찍기. 시장·경쟁 테스트는 웹서치로 직접 확인.
- 출력 `01_onething.md`:
  ```
  # 원씽 (확정)
  (누가)(어떤 상황에서)(뭐가 안 돼서)(어떤 결과)(무슨 방법) — 한 문장
  ## 쪼갠 후보 10+ (표)
  ## 4테스트 결과 (추천 후보 2~3개)
  ## 추천 이유 한 줄
  ## 1-3 리서치에 넘길 키워드 5~8개
  ```
- 이미 좁혀진 원씽이 들어왔으면 4테스트만 돌리고 통과 시 바로 저장.

### 02 리서치 (1-3, `market-validation.md` → `ebook-topic-research`)
- 입력: `01_onething.md` (원씽이 없으면 intake B 의 넓은 주제)
- 절차 a (시장 검증, `references/market-validation.md`): 키워드 5~8개를 유튜브·브런치·인스타·메타 광고·인프런·클래스101·탈잉 + 크몽·지식iN/카페·데이터랩에 돌려 채널별 ★ 판정 → 댓글·카페 글의 고객 언어를 원문·👍·출처 그대로 결핍 클러스터 5~7개로 묶음 → 10주제 표 → `02_market.md`. 주제명은 `ebook-title-monetize` 수익화 공식으로. 채팅에 표를 그대로 보여주고 사용자가 순위를 고르면 원씽 확정·갱신. 제목·부제 확정(00_intake A/B 갱신)도 같은 스킬로 10개 뽑아 고른다. 유튜브 검색 쿼터가 막히면 크롬 스크래핑 우회(파일 참고).
- 절차 b (심화): 스킬 그대로 — 리서치 지도 → 1차 국내/해외 병렬 → 2차 심화. intake F 의 깊이 설정을 따른다 ("생략"이면 a·b 를 approved 로 표시하고 건너뜀).
- 출력 `02_research.md` (스킬의 보고서 구조 그대로, 마크다운). 아티팩트/docx 발행은 이 파이프라인에서는 하지 않는다 — 파일이 산출물이다.
- **인용은 출처 URL·저자·연도가 있는 것만** 남긴다. 집필 단계에서 "실제 연구"로 쓸 수 있는 건 이 파일에 있는 것뿐이다. 없는 연구를 집필 중에 지어내지 않는다.

### 03 목차 (1-4, `ebook-outline`)
- 입력: `01_onething.md` + `02_market.md`(고객 언어·통념·10주제 표) + `02_research.md` + intake C(원료) + E(모드·챕터 수). 제목 후보와 정반합 과녁은 `02_market.md` 의 클러스터 최다 👍 문장·통념에서 먼저 뽑는다.
- 절차: 스킬 그대로 — 문제-해결 3단 표 → 뼈대 배치 → 자극 6종 × 문법 22종 → 3안 → 추천안. intake B 의 민감 주제가 "예"면 도발 게이트 적용.
- 출력: 사람이 읽는 요약(스킬 8번 출력 형식)을 화면에 보여주고, 확정된 추천안을 `03_outline.json` (`outline-schema.json`) 으로 저장.
- 각 챕터에 반드시 `track`(서사/방법) 과 `materials`(intake C 의 어느 원료를 쓰는지) 를 채운다. 방법 트랙은 책 전체 3~5개.
- 승인 후 제목·주장·결론은 집필 중 바꾸지 않는다. 바꿔야 하면 이 단계로 돌아온다.

### 04 집필 (1-5, `ebookmake` 분량·구조 규칙 + 문체 스킬)
- 입력: `03_outline.json` + `02_research.md` + intake C(5문항)/D + 문체 파일. `원료 경로: 경험 없음`이면 1인칭 고백 금지, 구성 사례·연구 인용으로
- 문체 파일: (a) `bj-essay-voice` 스킬 / (b) `00_voice.md` / (c) `voice-default.md`
- 절차:
  1. `04_book.json` 골격 생성 (title/author/meta/closing + chapters 빈 blocks). meta.authorIsBj, meta.cta, meta.ctaMode 를 intake 에서 채운다.
  2. **checkpoint**: 프롤로그 + 1장을 먼저 쓰고 멈춘다. 문체·수위·트랙이 맞는지 사용자 확인. 여기서 고친 방향이 나머지 전부에 적용된다.
  3. 나머지 챕터를 순서대로 쓴다. 챕터 하나 끝날 때마다 `04_book.json` 에 저장하고 `pipeline.json` 의 `writing.nextChapter` 를 올린다 (중단 시 재개 지점).
  4. 챕터마다 문체 스킬의 체크리스트를 돌리고 결과를 `04_review.md` 에 한 줄씩 기록.
  5. 전체 완료 후 `node validate_book.js 04_book.json` — 오류 0 이 될 때까지 고친다. 경고는 검토해서 의도된 것만 남긴다.
- 집필 규칙 요약 (자세한 건 각 스킬):
  - 챕터당 블록 10~16개, lead 로 열고 hook 으로 닫는다. point 1~2, quote ≤1.
  - 서사 트랙: list/steps/check/box 금지, 산문만. 대비는 대사로. 번호 리스트는 접두어 벗기고 문장으로 (함정 5).
  - 방법 트랙: 장면으로 열고 → 이름 붙은 기법 → steps/box/check 허용 → 여운으로 닫는다.
  - 공통 오프닝 정반합: 통념 인용 → 반박.
  - 수치는 intake C 의 실제 수치만. 연구 인용은 `02_research.md` 에 있는 것만.
  - CTA: meta.ctaMode 가 repeat 면 매 챕터 마지막 p 앞에 CTA 문장, restrained 면 프롤로그·에필로그에만. 문구는 meta.cta.
  - 저자가 병조쌤이 아니면 병조쌤/비라스/비제이라이프스쿨/리치코드 절대 금지. 병조쌤 본인이어도 비라스/비제이라이프스쿨 금지.
- 출력 요약: 챕터별 제목·블록 수·트랙, validate 결과, 예상 페이지.

### 05 디자인·출력 (1-6, HTML → PDF)
- 입력: `04_book.json` (validate 통과본) + intake E 의 프리셋(비우면 자동 추천) + 있으면 `book.images`
- 절차:
  ```
  cd <스킬>/scripts
  node pick_preset.js <책폴더>/04_book.json          # 메인·보조 추천 → 사용자 확인 (게이트)
  node build_ebook_html.js <책폴더>/04_book.json <책폴더>/05_ebook.pdf --preset EBxx [--sub EByy] [--no-images]
  python check_design.py <책폴더>/05_ebook.pdf --body-pt 10.5
  ```
- 프리셋 게이트: 메인·보조·표지 레이아웃·이미지 스타일을 한 줄로 보여주고 확인. 고민되면 후보 2개를 표지+본문 한 쪽씩 뽑아 고르게 한다.
- `check_design.py` 실패(글자 축소·빈 쪽·차례 불일치)면 고친 뒤에 보여준다. `_check.png` 시트로 가이드 최종 품질 체크리스트를 눈으로 본다.
- 삽화가 필요한 프리셋인데 그림이 없으면 벡터 표지로 뽑고 "그림을 주시면 표지·PART 에 넣는다"고 안내한다. 이미지 API 연동 전까지 그림은 사용자 제공.
- 디자인 단계에서 원고 문장을 고치지 않는다. 문장 문제는 04 로 돌아간다.
- 파일명은 영문 slug 기반. 최종본은 `books/<slug>/final/<slug>.pdf`. 수정용 docx 는 요청 시 구 빌더로.
- 출력 요약: 페이지 수, 프리셋(메인/보조), 표지 레이아웃, 그림 사용 여부, 검수 결과 한 줄.

### 09 메타 광고 소재 (ebook-meta-ads)
- 입력: 02_market.md(고객 언어·통념) + 04_book.json(프롤로그) + 05 표지 + 08_salespage(링크·팔레트)
- 절차: ebook-meta-ads SKILL.md 2장 그대로. 승인 게이트 3개(후킹 20 선택 / 소재 15 선택 / 업로드·예산).
- 출력: 09_hooks.md, 09_ads.json, ads/people/, ads/out/, 09_ads_sheet.png, 09_upload_plan.md, (업로드 시) 09_launch_log.md
- auto 모드에서도 승인 ③(돈이 나가는 업로드·예산)은 건너뛰지 않는다.

승인 게이트 (09 는 게이트가 3개다. 셋 다 통과해야 `status.js --set 09_ads approved`)
1. **승인 ① 후킹 20개 선택**: 후킹 뱅크 30개를 `09_hooks.md` 에 저장하고 표로 보여준 뒤 사용자가 20개를 고른다. 마음에 드는 게 없으면 다른 축(독자·상황·결과)으로 10개 더.
2. **승인 ② 소재 15개 선택**: 빌드한 `09_ads_sheet.png` 를 셀프 검수(checklist.md) 후 보여주고 사용자가 15개를 고른다(이미 돌고 있는 광고가 있으면 15 - 기존 개수).
3. **승인 ③ 업로드·예산**: 메타 업로드, 예산 변경, 광고 켜기는 금액을 한 줄로 말하고 확인받은 뒤에만 한다. 결과는 `09_launch_log.md`.
- auto 모드: 승인 ①·② 는 추천안으로 건너뛸 수 있지만 **승인 ③ 은 auto 에서도 반드시 멈춘다**(돈이 나간다).
- 광고 계정 정보(intake G)가 비어 있으면 업로드 없이 `09_upload_plan.md` 까지만 만들고 끝낸다.
- 이 파이프라인에는 아직 06~08 단계 파일이 없을 수 있다. `08_salespage` 가 없으면 링크는 `[상세페이지 URL]` 로 두고 사용자에게 받고, 팔레트는 ebook-meta-ads 기본값을 쓴다. 08 의 임시 후기(`sample:true`)는 광고에 쓰지 않는다.

## 재개 규칙

세션이 새로 시작되면 `node status.js books/<slug>` 부터. approved 가 아닌 첫 단계에서 이어간다. 04 단계면 `writing.nextChapter` 부터 쓴다. 이전 단계 파일을 다시 만들지 않는다.
